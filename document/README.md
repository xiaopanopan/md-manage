# md-manage 文档索引

本目录集中保存 md-manage 的现状说明、技术设计、调研结论与历史方案。阅读时应优先参考“当前有效文档”；`product/`、`design/` 和 `archive/` 中的内容用于追溯需求与设计过程，不保证与当前代码完全一致。

## 文档状态约定

| 状态 | 含义 |
|---|---|
| 当前有效 | 描述当前分支的实际实现，可作为开发和验收依据 |
| 规划建议 | 面向后续迭代的优化方向，不代表已经实现 |
| 历史资料 | 早期需求、设计或问题分析，仅用于背景参考 |

## 推荐阅读顺序

1. [项目 README](../README.md)：快速了解功能、运行方式和当前验证状态。
2. [技术架构文档](./技术架构文档.md)：理解进程边界、数据流、保存机制、安全模型与扩展方式。
3. [Tauri 迁移技术方案](./Tauri迁移技术方案.md)：了解 Electron 替换范围、实施结果、剩余风险与迁移门禁。
4. [项目调研报告](./项目调研报告.md)：了解代码审查、功能验证和问题判断。
5. [项目优化与重构方案](./项目优化与重构方案.md)：查看优化优先级、实施路线和后续技术债。
6. [左侧文件管理系统优化技术方案](./左侧文件管理系统优化技术方案.md)：查看基于 VS Code Explorer 调研形成的排序、选择、新建和拖拽重构规范。

## 维护规则

- 代码行为发生变化时，同步更新根目录 `README.md` 和本目录的技术架构文档。
- 尚未实施的内容必须标为“规划建议”，不要写成现有能力。
- 新的产品需求放入 `product/`，阶段性设计放入 `design/`，失效或已闭环资料移入 `archive/`。
- 文档中的路径、命令和 IPC 名称应以当前代码为准；提交前检查 Markdown 相对链接是否存在。
